# 0.6.0

First increment of the work-board plan: one board per game, opened by the Director.

- The Director opens the game's board as soon as the studio team is approved, before any hire arrives and before the project proposal. The board is unbound and Director-managed until the project exists.
- When that board exists, the Producer's project proposal starts as a board collaboration instead of a chat collaboration. A retry of a blocked proposal then returns the turn to the Producer. If the board grant is not approved or the board does not qualify for the pair, the previous chat collaboration starts unchanged.
- The Director's state records the board id from that moment, so its portfolio index resolves board-sourced turns to the right game.

New team-scoped grants: `work.board.create` and `communication.coordination.start-board.v1`. Both need approval on update. Without them nothing changes from 0.5.1.

Requires the matching platform build: `work.board.create` for a project now adopts the team's single empty pre-project board (binds it to the project, applies the project's board profile and makes the caller its manager) instead of creating a second board. The Producer needs no change for this.

Not in this release: cards for leadership work on the board, automatic resume after a specialist update for this collaboration, and opening the board at the moment of the owner's direction (a team does not exist until the staffing plan is approved).

Validation: `dotnet test` passes (owner run, 2026-11-10). The matching platform change builds and its `WorkManagementCapabilityHandlerTests` pass, including `ProjectBoardRequestAdoptsTheSupervisorsEmptyPreProjectTeamBoard`. Run the published output's `--self-test` before publishing. Not yet verified on a live company.
