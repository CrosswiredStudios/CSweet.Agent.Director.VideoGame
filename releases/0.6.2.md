# 0.6.2

Work-board plan, Director side: leadership collaborations after the proposal, and status from cards.

- The design-document commission to the Creative Director gets an owning card on the Director's agenda: "Get the game design document from the Creative Director". It is made with the SDK's `TrackedCollaboration` helper, bound to the project, the game board and the exact session, so it appears on the game board under "Leadership work" with Retry and Stop.
  - It waits while the collaboration runs, completes when the reviewed document is accepted, and is Blocked with a typed reason when the collaboration stops.
- When a turn arrives on a collaboration whose owning card is Blocked, the card returns to the queue and reports the current state. This is what brings a card back after Retry on the game board.
- A status answer in chat now names blocked leadership work for the game with its reason. It no longer reports a phase as pending or active while the card that owns it is blocked.
- Fix to 0.6.1: the proposal card now carries the game's intake fingerprint, so its callback finds the right game when the direction came through project intake. Without it the card could keep waiting after the project was created.

Requires `CSweet.Agent.SDK` 5.15.0, which must be published first. No new permissions beyond 0.6.1.

Not in this release: the proposal card still uses its own 0.6.1 code and has not moved to the SDK helper; cards for the creative review and technical handoffs.

Validation: not yet run. Written without a .NET SDK available; run `dotnet test` and the published output's `--self-test` before publishing.
