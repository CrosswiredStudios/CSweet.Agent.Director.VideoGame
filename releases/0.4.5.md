# 0.4.5

Project-proposal failures are durable manager-owned waits instead of repeated callback exceptions. Director reports the specific next action, preserves the accepted pitch/team/session, and journals one resume only when the current granted broker schema accepts previously rejected root fields. Unchanged errors, cancelled sessions, changed participants, missing pitch authority and turn limits retain their wait. Lost resume responses reuse the saved command; concurrent stale callbacks cannot overwrite a newer wait or restore a cleared one.

Proposal IDs retained in collaboration artifacts are recovered before considering resubmission, including a project already created by an approved proposal. Existing approvals, independent review, staffing and source permissions remain authoritative. No additional capability or network grant is requested.

Uses SDK 5.12.0 and Work Management Contracts 5.3.0. Publish/install with Producer 6.3.2 and restart C-Sweet with the matching broker schema fix. No database migration is required. The existing Super Awesome Games pitch and team can be retained; update through published releases and Installed Agents.

Verification covers corrected/unchanged contracts, repeated wakes, lost responses before/after resume commit, stale callback merges, changed or revoked evidence, cancelled/limited sessions and recovery of a committed proposal from its transcript. See C-Sweet's project-proposal recovery document for verification and live-rollout status.
