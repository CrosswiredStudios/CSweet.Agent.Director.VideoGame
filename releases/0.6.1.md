# 0.6.1

Second increment of the work-board plan, Director side.

- A board-sourced project proposal now gets an owning card on the Director's agenda: "Get the Producer's project proposal approved". Its work context carries the game board and the exact collaboration session.
  - While the collaboration is active the card waits. When the project exists it completes.
  - When the collaboration is blocked, failed or cancelled the card is **Blocked** with the collaboration's summary. That is the state the platform's board recovery acts on: moving the card back to To Do resumes the collaboration with a fresh Producer response, and an update of the Producer's package after the block does the same automatically.
- The game board is named after the game. `GameBoardName` removes the pitch document label ("Game Pitch", "Official Game Pitch") and surrounding quotes from the pitch heading in code.

- Agenda cards the Director creates after the board opens and before the project exists (the Producer documentation handoff) name the game board in their work context. With the matching platform build they appear on the game board under "Leadership work". Cards created once the project exists keep their project-scoped context unchanged.

- When the board opens, the cards that predate it (the pitch and the staffing plan) are bound to it, so the board shows the game's history from the first direction. `BindEarlierCardsToGameBoardAsync` changes only the cards' work context, only on this Director's own cards for that game, and is safe to repeat.

One new permission: `work.personal-todo.update.v1`, used only for that binding. Approve it when updating; without it the earlier cards stay on the Director's own board and everything else works. Works without a platform change; the "Leadership work" strip needs the platform build that adds linked commitments to the board read.

Not in this release: showing these cards on the game board itself (the card is on the Director's personal board), a card for the design document, and opening the board at the owner's first direction (the studio team, and so the board, exists only once the staffing plan is approved).

Validation: not yet run. Written without a .NET SDK available; run `dotnet test` and the published output's `--self-test` before publishing.
